## Problème

Une tontine repose sur la confiance : chaque membre cotise à chaque cycle, et un membre reçoit la cagnotte à tour de rôle. Quand le suivi se fait sur papier ou dans un tableur, l'organisateur recalcule lui-même les retards, les dettes et les pénalités. Une erreur corrigée en écrasant une valeur fait disparaître l'information d'origine, et personne ne peut vérifier comment un solde a été obtenu.

## Ma contribution

Projet personnel réalisé seul, d'avril à septembre 2026 (162 commits) : modélisation des données, API Express, interface React, tests, conteneurisation Docker et déploiement sur Render.

## Solution

**Pour l'organisateur du groupe**

- Création de groupes, de membres et de cycles de cotisation.
- Pénalités de retard appliquées par une tâche planifiée.
- Correction d'une transaction sous forme d'écritures d'annulation et de remplacement, visibles dans l'historique.
- Export PDF d'un cycle et export Excel d'un groupe.

**Pour les membres**

- Suivi de ses cotisations, de ses dettes et de l'historique des transactions.
- Rappels avant échéance et alertes de retard sous forme de notifications dans l'application, avec affichage des montants dans la devise choisie.

### Architecture

<Diagram />

L'API suit un découpage contrôleur → service → modèle : le contrôleur valide la requête, le service porte les règles métier (calcul des dettes, écritures de compensation), le modèle décrit le schéma Mongoose. Les tâches cron tournent dans le même processus que l'API : clôture des cycles expirés, application des pénalités, rappels J-3, alertes de retard et nettoyage des notifications.

### Sécurité

- Jeton d'accès JWT et jeton de rafraîchissement stocké dans un cookie `httpOnly`, renouvelé à chaque rafraîchissement.
- En-têtes HTTP via Helmet, CORS restreint, limitation du nombre de requêtes sur l'API et sur les routes d'authentification.
- Correction de transaction réservée à l'admin du groupe, vérifiée dans le service.

### Tests et qualité

Les tests d'intégration tournent sur une base MongoDB en mémoire (MongoMemoryServer), sans connexion à Atlas. Ils couvrent l'authentification, les groupes et les cotisations ; des tests unitaires couvrent les calculs financiers. Les tests ne tournent pas en intégration continue : ils sont lancés à la main.
