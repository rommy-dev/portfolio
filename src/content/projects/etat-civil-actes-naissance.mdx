## Problème

Des actes de naissance existent sur papier dans les centres d'état civil et doivent être enregistrés après coup dans un système numérique, avec la localisation administrative (région, district, commune, fokontany) et les personnes liées à l'acte.

Avant ce projet, les actes de naissance étaient tenus uniquement sur des registres papier.

## Ma contribution

Stage au Ministère de l'Intérieur et de la Décentralisation, de janvier à avril 2026 (premier commit le 15 janvier, dernier commit de code le 26 avril). J'ai travaillé seul sur le développement, encadré par le chef du service de maintenance des systèmes informatiques.

- Backend : API Symfony 7 / API Platform, modèle de données (acte, déclarant, responsables légaux, mentions marginales, jugements supplétifs, informations obstétricales), règles de validation.
- Frontend : interface React en TypeScript (saisie, liste, filtres, décisions).
- Authentification par jeton JWT et contrôle d'accès par rôle.
- Tests automatisés backend et frontend.
- Documentation : guide utilisateur pour les secrétaires et officiers, plan de tests d'API, procédure de déploiement.

Je n'ai pas réalisé la mise en production : la procédure de déploiement est une documentation remise au Ministère.

## Solution

**Pour les secrétaires (saisie)**

- Création d'un acte de naissance : identification, localisation administrative (région, district, commune, fokontany), type d'enregistrement, enfant, état de naissance.
- Fiches liées à l'acte : déclarant, responsables légaux, jugement supplétif, mention marginale, informations obstétricales.
- Liste des actes paginée, avec recherche et filtres (sexe, statut, type).

**Pour les officiers d'état civil (contrôle)**

- Validation d'un acte en attente, ou refus et annulation avec motif obligatoire.

**Pour les administrateurs**

- Gestion des comptes et des rôles : administrateur, officier, secrétaire, lecture seule.

## Résultats

Le développement est terminé et a été remis au Ministère avec un guide utilisateur et une procédure de déploiement. Je n'ai pas d'information sur l'utilisation de l'application depuis la fin de mon stage, donc pas de données d'usage.

### Architecture

<Diagram />

Le backend Symfony expose les données métier avec API Platform et Doctrine ORM. L'interface React en TypeScript (Vite) consomme cette API.

### Sécurité

Mesures en place dans le code, décrites sans détail d'implémentation :

- Connexion obligatoire avant tout accès aux données.
- Jeton JWT transmis dans un cookie HttpOnly (illisible par le JavaScript de la page) et SameSite=Lax.
- Contrôle d'accès par rôle côté API : seuls secrétaires et administrateurs créent un acte, seuls les officiers le valident.
- Un compte créé par inscription reçoit uniquement le rôle lecture seule ; les rôles envoyés par le client sont ignorés.
- Auteur de chaque création et modification enregistré sur les fiches.

### Tests et qualité

- Backend : 33 tests unitaires PHPUnit sur l'entité Acte de naissance (règles métier et contraintes de validation), 98 assertions.
- Frontend : 16 tests Jest (connexion, liste des actes, hook de recherche).

Dernière exécution le 14 novembre 2026 (PHPUnit 12.5, PHP 8.3 ; Jest) : tous les tests passent, avec 18 avertissements (notices) de PHPUnit. Un plan de tests d'API (Postman) décrit en plus les cas 401, 403 et 404.
